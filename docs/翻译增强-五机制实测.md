# 翻译增强五机制：借鉴 GalTransl / SakuraLLM 的实测记录（v1.30.6）

> 起点：用户看到两个 B 站项目（AITranslator V2.0、Faster Whisper GUI），
> 要求「深入挖掘五个能借的点并优化」。真正可借鉴的工程机制来自
> [GalTransl](https://github.com/GalTransl/GalTransl)（Galgame 自动翻译）
> 与 [SakuraLLM](https://github.com/SakuraLLM/SakuraLLM)（轻小说翻译模型）。
>
> 本文只记**实测**结论，不做未经测过的承诺。

## 总表

| 机制 | 实现 | 实测结论 | 默认 |
|---|---|---|---|
| ① 多轮上下文（前 N 句作对话历史） | `_raw_completion(ctx=, _CTX_STYLE="turns")` | **负面**：sim 0.4653→0.4040，逐条 11 好 / 25 差，且慢 2.5 倍 | **关** |
| ② 上下文降级为「上一句提示」 | `_CTX_STYLE="hint"` | 中性：sim −0.0075（噪声级），人称有修正；但 system 每句变 → 缓存失效，**80.9→25.3 段/分** | **关**（`ASMR_TRANSLATE_CTX=8` 可开） |
| ③ GPT 字典（日文/TAB/中文/TAB/解释，按句注入） | `load_glossary` 三列 + `_glossary_prompt` | **有效**：`凪咲、どこに行ったの？` 无字典「阿奈去哪了？」→ 有字典「凪咲去哪了？」；`先生` → 「老师」；无关句子一字不动 | **开** |
| ④ 译前字典 / 条件字典 | `terms_fix.py` 支持 `pre:` 与 `\|条件` | 机制就位，自测通过（保护条件词不被切开） | 开（词表默认为空） |
| ⑤ 自动化找错（残留日文 / 空译文 / 超长） | `_quality_issues` + `translate` 重试 | 机制就位；`kana`/`empty` 会重试，`long` 只统计 | 开 |

## 一、为什么多轮上下文在我们这里反而更差

GalTransl 的做法是把前 8 句译文当**对话历史**喂进去。我们照做后：

```
[0] 日: ある 気がつきましたか? 射精で疲れ果てて…
    A(单句): 你有没有注意到？因为精液的刺激而精疲力竭失去意识…
    B(多轮): 有感觉了吗？精液的刺激会让人精疲力尽失去意识…
[6] 日: nいいです 電話 追加で罰を与えましょうか?
    A: 来吧 给你点颜色看看
    B: 好舒服啊          ← 完全跑偏
```

40 句 A/B（真起 llama-server + 挂 v5 LoRA，CPU）：

| | sim | f1 | 耗时 |
|---|---|---|---|
| A 单句 | 0.4653 | 0.2800 | 33.4 s |
| B 多轮 8 | 0.4040 | 0.2168 | 84.5 s |

逐条：B 更好 11 / 更差 25 / 持平 4，平均差 **−0.0613**。

**根因**：LoRA 只在「单轮、`BOS+SYSTEM+USER+日文+ASSIST`」这一种格式上训过，
突然给它多轮历史属于**格式错配** —— 和 v1.30.3 那个「chat 模板与 hy 模板对不上、
挂 LoRA 就吐 `<|<|<|`」是同一类问题。小模型（1.8B）对格式比大模型敏感得多。

## 二、降级成「上一句提示」：不亏但也赚不到

把上一句写成 system 里的一行，仍是单轮：

```
上一句（仅供理解上下文，不要重复它的内容）：<日文> → <中文>
```

A/B 结果（同一测试集）：

| | sim | f1 | 耗时 |
|---|---|---|---|
| A 单句 | 0.4569 | 0.2784 | 41.5 s |
| B hint | 0.4494 | 0.2662 | 39.3 s |

逐条：hint 更好 8 / 更差 18 / 持平 14，平均差 **−0.0075**（两次跑 A 本身就有 ±0.008 波动）。

**人称确实修好了**（这就是它的价值）：

```
[7] 日: ああ、もちろん、あなたに拒否権なんてありませんので
    A: 啊，当然了，我也没有拒绝权哦     ← 主语错（あなた = 你）
    B: 当然了，你也没有拒绝权           ← 正确
```

**但速度代价致命**：system 每句都不一样 → llama.cpp 的 `cache_prompt` 前缀缓存全废，
每个句子都要重新 prefill。端到端实测 `a120` 8 段：**80.9 段/分 → 25.3 段/分（3.2 倍慢）**。
关掉后回到 55.9 段/分（8 段太少，含启动开销，实际稳态更高）。

结论：**默认关闭**，开关 `ASMR_TRANSLATE_CTX=8` 留着给愿意用时间换质量的场景。

## 三、GPT 字典：这一步是真提升

### 格式（TAB 分隔，写进 `hotwords.txt`）

```
凪咲	凪咲	name, girl, 女主角
先生	老师	teacher, 男性
```

第三个字段是「解释」，借鉴 Sakura 的 `src->dst #info`：写角色设定，
模型才知道「她/他」该选哪个、「先生」是老师不是丈夫。

### 实测（同一 server、同一温度）

| 原文 | 无字典 | 有字典 |
|---|---|---|
| 凪咲、どこに行ったの？ | 那个，阿奈去哪了？ | **凪咲去哪了？** |
| 先生、これはなんですか | 先生，这是什么呢？ | **老师，这是什么呀？** |
| 全然関係ない話だけど… | 虽然完全不相关的事情… | 虽然完全不相关的事情…（一字未变） |

第三行是关键：**按句注入**（只注入这句话里出现的词），所以无关句子完全不受影响。
老格式（逗号分隔、无译文）仍然支持，按「专有名词原样保留」处理。

## 四、译前字典 / 条件字典

GalTransl 的 `pre_jp / post_jp` + 判断词，简化成三行语法写进 `fixes.txt`：

```
渚沙=凪咲                 # 译后替换（原有）
pre:ぺろぺろ=れろれろ      # 译前替换（改日文原文，字幕仍保留原文）
乳=奶|乳头                # 条件替换：译文里有「乳头」才替换「乳」
```

条件替换会**保护条件词本身**：`乳=奶|乳头` 作用在「乳头和乳」上得「乳头和奶」，
不会把「乳头」切成「奶头」（`_replace_outside()`）。

全量/精简模式不经过翻译层，所以只吃 1) 译后替换 —— 这一层在 Rust `srt.rs` 里读同一个文件。

## 五、自动化找错

| 检查 | 判定 | 处理 |
|---|---|---|
| `kana` | 译文里还有假名 = 根本没翻（1.8B 偶尔原样吐日文） | 重试（换温度） |
| `empty` | 去掉标点后为空 | 重试 |
| `long` | 比原文长 2.2 倍以上 | **只统计不作废**（「ちょっと」→「稍微等一下嘛」是合法的） |

## 八、v8：术语表注入 LoRA —— 负结果，路线关闭（2026-11-22）

### 8.1 为什么想训
Sakura 的术语表能力是 **SFT + RLHF 训出来的**，不是靠 prompt。我们推理侧按句注入虽有效（见第三节），但实测**只要 system 里出现「术语表」段就掉质量**（30 条 ASMR 台词、同一 v5 模型）：

| 组 | 说明 | sim | f1 |
|---|---|---|---|
| A | 无术语表 | **0.5657** | **0.4239** |
| B | + 2 条句中不出现的无关术语 | 0.5226 | 0.3677 |
| C | + 2 条本句真实汉字串 | 0.5254 | 0.3695 |

掉 7.6% / 13.3%，还会把无关术语硬塞进译文（`れいなのお願い聞いて?ぬるぬるで、` → 「怜奈的**肉棒**好硬啊」）。所以想训一版「带表不掉质」的 LoRA。

### 8.2 术语数据：三次都失败
| 来源 | 结果 |
|---|---|
| `mine_terms_v2.py` 全局挖（22,826 条 clean 句对） | 436 条，前 10 全是功能词（`それでは→那么`、`じゃあ→那么`），模型本来就会 |
| `build_terms_v8.py` 按单作品专名重挖 | 44 条，混着 `学校/最近/健康` 等同形词；真名（`凪咲`）每部只 5~30 句，挖不到 |
| 素材里的 `Script_*.txt` 日文台本 | 全盘 13 个，真日文只有 1 个 |
（素材里的 `*.txt` 多数是 `.vtt` 的副本，含 `WEBVTT` 头 + 中文字幕，不是台本。）

### 8.3 训练配置
- `train_lora.py` 新增：`BUILTIN`（把生产的术语/拟声提示搬进训练 system）、`GLOSS_RATIO=0.40`、`GLOSS_NOISE=0.35`、`gloss_block()`/`build_text(ja,zh,gloss_pairs)`/`prompt_text()`、`DS._gloss_for()`（按句抽真实汉字串，40% 带表，35% 掺无关串）、`max_length` 256→**448**（实测 p90=359、max=420）。
- 训练：`BS=2 ACC=8 MAX_STEPS=500 OPTIM=adamw_torch` → **4.1~4.5 s/it、显存 10.4GB、40.4 分钟**；`train_loss 1.116 / eval_loss 1.029`。
- 产物 `H:/_train_models/adapter_v8`（87.2MB）→ `hy-mt2-asmr-lora-v8.gguf`（77,625,376 B）。

### 8.4 评测一：术语遵守率（10 个反直觉术语）
| | v5 | v8 |
|---|---|---|
| 遵守率 | **70% (7/10)** | **40% (4/10)** ✗ |
| 溢散 | 0/4 | 0/4 |

v5 听话的例子：`先生->大夫` → 「大夫，这是什么呀」；`ご主人様->少爷` → 「少爷，回来了」；`アナル->后面` → 「后面」。
v8 反而无视：`先生->大夫` → 「**老师**，这个是什么？」；`ご主人様->少爷` → 「**主人**，回来了」；`アナル->后面` → 「不要做**口交**了」。

**根因（我的设计错误）**：训练注入的术语全是 `X->X`（映射 100% 正确、零噪声），模型学到的是「术语表里的 dst 可以忽略」，专名保住了，但 `先生->大夫` 这种**改写**丢了。

### 8.5 评测二：ASMR val（同口径，120 条全对应）
| | v5 | v8 | 配对差 |
|---|---|---|---|
| sim | **0.5040** | 0.4726 | **−0.0314 ± 0.0131（2.4σ）** |
| f1 | **0.3282** | 0.3126 | −0.0155 ± 0.0146（1.1σ） |

逐条：18 更好 / 37 更差 / 65 持平。
退化最狠的一条（v8 幻觉插入）：
- 原文 `い吸われながら、下からちんぽ突き上げられて、`
- 参考「一边被吸着胸部，一边被肉棒猛烈顶撞♡」/ v5「一边被吸着一边被肉棒顶着」/ **v8「被爸爸的精液射出来，从下面插进去了」**

### 8.6 结论与教训
**v8 三项全败**：遵守率 40%<70%、val 显著退化 2.4σ、还新增幻觉。**不上线**，生产仍用 v5（`hy-mt2-asmr-lora.gguf` md5 `3eb694bc…`）。`adapter_v8` / `v8.gguf` 留档在 `H:\_train_models\`。

1. **没有可靠术语数据就不该训术语表能力**：`X->X` 教不出「dst 优先」，还会诱导模型往译文里塞汉字词（幻觉）。
2. **评测口径必须先固定 val 集**：`make_splits` 的「最小作品做 val」会随语料构成变（v5 vs v8 的 val 交集只有 3/120），跨版本比较必须 `EVAL_SRC` 固定数据源，并重测旧版本基线。
3. 推理侧注入术语表**本身有代价**（sim −7.6%），只在「专名会丢」的句子上收益超过代价 —— 这也是按句注入优于全局注入的原因，但它不免费。

### 8.7 术语表的真实价值（意外发现）
`凪咲、どこに行ったの？` **不给表时 v5 会把整个人名丢掉**（「那 你去了哪里？」），给表就正确。所以术语表的作用不是「统一译名」，而是**保住本来会丢的专名**。据此 `_glossary_prompt` 保留、默认空表，只在用户确实需要固定人名/译名时才填。
