# ASMR 自动翻译工具 v1.24.1

把日语 ASMR 音声 / 视频批量翻译成中文字幕（`.chs.srt`），字幕直接生成在源文件旁边，播放器可以自动加载。

**处理过程全程离线**，不联网、不上传任何文件。界面是 Rust + WinUI 3，AI 推理跑在本地的 Python 环境里。

## 安装

1. 双击 `ASMR-Translator-Setup.exe`（主程序安装包，网盘下载的叫 `1_主程序_安装包.exe`，同一个东西）→ 一路下一步，**中途会弹一次管理员授权（UAC），点「是」**
2. 解压 `运行环境.zip`，双击里面的 `2_运行环境_安装包.exe` → 一路下一步（同样要授权）

先装哪个都行。两个包装到同一个目录 **`C:\Program Files\ASMR自动翻译工具`**，共用同一个卸载入口。

> 为什么要管理员权限：装到 `Program Files` 是 Windows 的标准做法，卸载列表里能看到，
> 也不会因为装在用户目录里被某些备份/清理工具误删。程序本身不往注册表乱写东西。

**你的数据放在哪**：处理过程中的中间文件、日志、断点续传队列不在 `Program Files` 里
（那里普通权限写不进去），而在 `%LOCALAPPDATA%\ASMR自动翻译工具\`。
字幕文件仍然直接生成在**视频旁边**，这一点没变。

装完桌面会有快捷方式「ASMR 自动翻译工具」。

### 安装前请确认

- **磁盘空间 ≥ 7 GB**（程序 17 MB + 环境 5.6 GB + 模型 5.3 GB，安装过程还要临时占用）
- **管理员权限**（装到 `C:\Program Files` 需要，安装时弹一次 UAC）
- **Windows 10 1809 或更高**（WinUI 3 的硬性要求，Win11 当然可以）
- Windows Defender 或其它杀软如果拦截，选择「允许」。弹「Windows 已保护你的电脑」时，点「**更多信息**」→「**仍要运行**」。安装包没有数字签名，被这样拦一下是正常的

## 用起来

1. 拖视频/音频文件进窗口，或者点「添加文件」「添加文件夹」
2. 选处理模式（见下表）
3. 点「开始处理」
4. 等它跑完，字幕出现在源文件旁边，文件名是 `原文件名.chs.srt`

| 模式 | 显存要求 | 用的是 | 速度 |
|---|---|---|---|
| 全量模式 | ≥ 8 GB | whisper large-v2（CUDA） | 最快 |
| 精简模式 | ≥ 6 GB | 同上，模型量化版 | 快 |
| 兼容模式 | < 6 GB / 非 N 卡 / 核显 | SenseVoice + Qwen（Vulkan 或 CPU） | 慢一些 |

程序会自动检测你的显卡，并**禁用跑不动的模式**。副标题会显示当前用哪个后端在加速。

> **第一次启动会慢一点**（十几秒到半分钟）：要初始化 Python 环境、加载模型，杀软还要把 17 MB 的程序扫一遍。之后再开就快了。这段时间界面可能停在「检测中…」，是正常的，别急着关。

## 常见问题

**Q：网盘里的运行环境是 5 个文件，怎么装？**
解压 `运行环境.zip`，5 个文件会一起出来。保持它们在同一个文件夹，双击 `2_运行环境_安装包.exe` 即可，它会自动找旁边的 `.bin` 分卷。

**Q：装完打开报错 / 一直「检测中…」**
按顺序查三件事：
1. **两个包都装了吗？** 只装主程序包的话，程序找不到 `env\python.exe` 和模型，会一直卡在设备检测。
2. **等够半分钟了吗？** 第一次启动要初始化环境，慢是正常的。
3. **是不是杀软把文件隔离了？** 去 Windows 安全中心 →「病毒和威胁防护」→「保护历史记录」看看有没有被删的文件，有就恢复并加白名单。

**Q：提示「未检测到 NVIDIA 显卡」，只能选兼容模式**
正常。要么你的卡不是 NVIDIA，要么驱动太旧。装最新驱动，或者就用兼容模式（同一套流程，只是慢）。

**Q：杀毒软件报毒**
安装包没有数字签名，是自解压式的 Inno Setup 安装包，容易被误报。程序本身不联网、不写注册表以外的地方，源码全部公开在这个仓库里。

**Q：字幕在播放器里不显示**
字幕文件是 `xxx.chs.srt`，播放器需要手动选「加载字幕」，或者把播放器设为自动加载同名字幕（PotPlayer、mpv、VLC 都能设）。

**Q：想换机器 / 重装**
直接重装两个包即可，程序没有联网激活、没有机器绑定。

**Q：出问题了，日志在哪？**
程序的运行日志在 `%LOCALAPPDATA%\ASMR自动翻译工具\_运行日志.txt`，界面上的「导出完整日志」按钮也能直接存一份。
（程序的「运行日志」面板开头会写明这次用的是哪个数据目录，照着找就行。）
所有处理都在本地完成，不上传任何内容；日志也只写在这个目录里，随时可以删。

**Q：还有别的问题 / 想提建议？**
来 [Issues](https://github.com/T2887/asmr-translator/issues) 说一声，附上日志里的报错行会快很多。

**卸载**：设置 → 应用 → 「ASMR 自动翻译工具」→ 卸载。**两个包共用一个卸载入口**，卸载时程序和运行环境会一起删掉，不用手动清理。

## 这一版改了什么（v1.24.1）

**兼容模式选卡顺序修正。** 原来的顺序是「核显 → 非 N 独显 → N 卡兜底 → CPU」，
本意是「别跟 N 卡抢显存」，但副作用是：一台装了 AMD RX 或 Intel Arc 独立显卡的
机器，兼容模式会放着独显不用、让核显慢慢跑。现在改成「**非 N 独显 → 核显 → N 卡
兜底 → CPU**」——「不吃 N 卡」这条只对 N 卡成立，不该顺带把独显也降级。

顺带修了核显 / 独显的判定：`AMD Radeon 780M` 这类 APU 核显名字里既没有 RX 也没有
Graphics，以前会漏判成独显；`Intel Iris Xe MAX` 是独显，以前会被 `iris` 误判成核显。
名字都没命中时按显存大小兜底（核显报的是共享内存，经常上万 MiB）。

## 上一版改了什么（v1.24.0）

**能装进 `C:\Program Files` 了。** 改动在程序内部：把「程序目录」和「运行数据目录」拆开 ——
程序目录（exe、脚本、Python 环境、模型）只读，日志和中间文件落到 `%LOCALAPPDATA%`。
以前两者是同一个目录，装到 `Program Files` 会因为写不进去而跑不起来（建不出中间目录，
字幕也没地方落）。

**显存被占满时，设备状态不再说错话。** 以前 N 卡显存被别的程序占着、兼容模式又枚举不到
Vulkan 设备时，界面写「CPU：未找到可用的 Vulkan 设备」，看着像驱动坏了。现在会写明
「剩余显存 x.x GB，低于兼容模式要求，已切换至 CPU 推理」。顺带修了剩余显存的取法 ——
WDDM 下 `torch` 报的可用显存会高估好几倍（实测 nvidia-smi 报 988 MiB、torch 报 7.2 GB），
改用 `nvidia-smi` 读数。

完整改动见 [提交记录](https://github.com/T2887/asmr-translator/commits/main)。
